# MCO Daily — 8 octobre 2026

## Résumé exécutif

🟠 **Proxmox : mouvement kernel important.** Les métadonnées officielles Proxmox publiées le 7 octobre exposent désormais les changelogs `7.0.14-21` et `7.0.14-22`. `-22` n'est donc plus uniquement un build de test. Vu les régressions observées avec `-20`, tester `-22` en priorité sur un nœud pilote avant généralisation.

🟡 **Rocky/RHEL 9 : aucun nouveau kernel.** `5.14.0-687.54.1.el9_8` reste la cible.

🟡 **GitLab : pas de nouvelle Critical Patch Release CE/EE identifiée ce matin.** Les correctifs critiques précédemment publiés restent prioritaires. GitLab 19.5 est documenté/préparé mais aucune publication stable 19.5 n'est retenue dans ce brief.

# Rocky Linux / RHEL 9

## Kernel de référence

```text
5.14.0-687.54.1.el9_8
```

Le dépôt officiel Rocky Linux 9 BaseOS x86_64 confirme toujours `687.54.1`, daté du 2 octobre, comme kernel le plus récent.

Le correctif précédent reste donc la cible MCO. Aucune version `687.55+` n'a été trouvée au moment du contrôle.

### Vulnérabilités

La vigilance sur **CVE-2026-100070** reste ouverte : Red Hat indiquait RHEL 9 kernel en état `Fix deferred` lors du dernier contrôle. Aucun nouveau kernel Rocky/RHEL 9 publié aujourd'hui ne permet de modifier cette recommandation.

**Action MCO :**
- maintenir/déployer `5.14.0-687.54.1.el9_8` ;
- redémarrer les machines mises à jour et contrôler le kernel actif ;
- poursuivre la surveillance des CVE kernel sans correctif RHEL 9 disponible.

# Proxmox VE

## Nouveau kernel Proxmox

Les métadonnées officielles Proxmox datées du 7 octobre publient désormais les changelogs :

```text
proxmox-kernel-7.0_7.0.14-21
proxmox-kernel-7.0_7.0.14-22
proxmox-kernel-signed-7.0_7.0.14+21
proxmox-kernel-signed-7.0_7.0.14+22
```

C'est le changement MCO principal du jour.

Le dépôt no-subscription a été actualisé le 7 octobre et référence la famille `proxmox-kernel-7.0`. Les métadonnées Enterprise montrent également `+21` et `+22`.

`pve-manager` reste en **9.2.21** : aucun `9.2.22` n'est présent dans l'index no-subscription contrôlé.

### Recommandation parc

Compte tenu des régressions suivies avec `7.0.14-20-pve` ces derniers jours, la présence de `-22` est particulièrement intéressante.

**Action MCO :**
- tester `7.0.14-22-pve` sur un nœud pilote ;
- vérifier réseau, PCIe/AER, RTC, stockage et démarrage des VM après reboot ;
- conserver au moins `7.0.14-19-pve` bootable pendant la validation ;
- ne généraliser `-22` qu'après validation du pilote.

# GitLab Self-Managed

## État des releases

Aucune nouvelle **Security/Critical Patch Release CE/EE** postérieure aux correctifs déjà suivis n'a été identifiée au moment du contrôle.

Les cibles de sécurité restent :

```text
19.4.x -> 19.4.1
19.3.x -> 19.3.3
19.2.x -> 19.2.7
```

Les vulnérabilités prioritaires restent :

- **CVE-2026-89078 — Critical / CVSS 9.9 — RCE CI/CD** : réseau, utilisateur authentifié à faibles privilèges, pas d'interaction utilisateur.
- **CVE-2026-93577 — Critical / CVSS 9.9 — RCE CI/CD** : réseau, utilisateur authentifié à faibles privilèges, pas d'interaction utilisateur.
- **CVE-2026-92470 — High / CVSS 7.7 — fuite de variables CI/CD via Duo AI**.
- **CVE-2026-92874 — Medium / CVSS 5.4 — portée/permissions de token MCP**.
- **CVE-2026-4523 — Low / CVSS 3.7 — accès non authentifié à certaines traces CI/CD**.

Aucun nouvel **auth bypass critique** n'a été identifié aujourd'hui.

La documentation GitLab contient déjà les notes d'upgrade vers **19.5.0**, notamment :
