# MCO Daily — 2 octobre 2026

## Résumé exécutif

🔴 **Rocky/RHEL 9** : la cible MCO reste le nouveau kernel `5.14.0-687.53.1.el9_8` (RHSA-2026:72623). Il corrige 9 CVE kernel supplémentaires. Les plus préoccupantes du lot incluent des vulnérabilités locales de corruption mémoire/élévation de privilèges ; aucune nouvelle version Rocky 9 x86_64 postérieure à `687.53.1` n'est identifiée ce matin.

🔴 **GitLab** : aucune Critical Patch Release plus récente identifiée. Les versions de sécurité restent `19.4.1`, `19.3.3`, `19.2.7`. Les deux RCE CI/CD CVSS 9.9 du correctif du 23 septembre restent prioritaires.

🟡 **Proxmox VE** : aucun nouveau `pve-manager` après `9.2.21` dans le dépôt no-subscription. Pas de nouveau kernel PVE promu nécessitant de modifier la référence production suivie `7.0.14-19-pve`.

# Rocky Linux / RHEL 9

## Kernel cible

```text
5.14.0-687.53.1.el9_8
RHSA-2026:72623
Rocky BaseOS : publié le 29 septembre 2026
```

Le dépôt Rocky Linux 9 BaseOS x86_64 confirme `687.53.1` comme dernier kernel publié dans la série suivie.

### CVE corrigées par RHSA-2026:72623

| CVE | Risque / impact défensif | Conditions principales |
|---|---|---|
| CVE-2026-45942 | ext4, race condition pouvant conduire à incohérence/corruption du bitmap | local, faibles privilèges |
| CVE-2026-46325 | vulnérabilité kernel corrigée par le build `687.53.1` | exposition dépendante du sous-système |
| CVE-2026-52972 | **Important, CVSS Red Hat 7.0** — overflow dans `af_alg`, corruption/instabilité possible | local, AC:H, PR:L, UI:N |
| CVE-2026-53341 | use-after-free lié aux file handles/mount namespace ; crash et impact mémoire possibles | local, faibles privilèges, race condition |
| CVE-2026-63875 | **Important, CVSS Red Hat 7.0** — gestion TLB arm64, accès mémoire non autorisé / élévation possible | local, AC:H, PR:L, UI:N ; principalement arm64 |
| CVE-2026-64102 | RDMA/siw, sous-dépassement de longueur MPA pouvant affecter mémoire/disponibilité | dépend de l'utilisation du sous-système Soft-iWARP |
| CVE-2026-64556 | vulnérabilité kernel corrigée par le build `687.53.1` | exposition dépendante du sous-système |
| CVE-2026-74753 | **CVSS Red Hat 7.8** — use-after-free dans `perf`, DoS et élévation de privilèges potentielle | local, AC:L, PR:L, UI:N |
| CVE-2026-80522 | **Important, CVSS Red Hat 7.8** — write out-of-bounds dans le crypto Tegra, crash/corruption mémoire | local, AC:L, PR:L, UI:N ; matériel/module Tegra |

### Priorité

Pour un parc Rocky x86_64 classique, les vulnérabilités spécifiques arm64/Tegra ont une pertinence opérationnelle faible. En revanche, les problèmes génériques ext4, perf, file handles et crypto justifient le déploiement du kernel corrigé.

**Action MCO :**
- déployer `5.14.0-687.53.1.el9_8` ;
- planifier le reboot ;
- confirmer ensuite `uname -r` ;
- ne pas considérer la simple installation RPM comme suffisante tant que le nouveau kernel n'est pas actif.

### Signaux MCO

- **RCE :** CVE-2026-89078 et CVE-2026-93577.
- **CI/CD :** RCE et exposition potentielle de variables/traces.
- **Secrets/tokens :** CVE-2026-92470 et CVE-2026-92874.
- **Sans authentification :** CVE-2026-4523.
- **Auth bypass critique :** aucun nouveau cas critique identifié dans le patch suivi.

**Action :** toute instance vulnérable doit être sur au minimum le patch corrigé de sa branche. Une instance encore en `19.3.2` doit passer en `19.3.3` ou version ultérieure supportée.

# Proxmox VE

## État du jour

```text
Proxmox VE       9.2
pve-manager      9.2.21
kernel prod      7.0.14-19-pve
```

Le dépôt officiel no-subscription ne montre pas de `pve-manager` supérieur à `9.2.21` ce matin.

`9.2.21` reste surtout pertinent pour les clusters Ceph/Cephx : nettoyage de clés d'OSD chiffrés, corrections FQDN pendant les opérations Ceph et garde-fous supplémentaires lors des migrations de clés.

Aucun nouveau kernel PVE promu dans le dépôt habituel ne justifie de changer la référence production suivie.

- intégrer `pve-manager 9.2.21` dans la fenêtre normale, avec priorité aux clusters Ceph ;

- ne pas promouvoir un build provenant uniquement d'un canal de test.
