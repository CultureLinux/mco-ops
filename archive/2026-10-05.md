# GitLab Self-Managed

## Nouveau : CVE-2026-90970 — GitLab Self-Hosted AI Gateway

**Criticité : Critical — CVSS 9.9**

```text
CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H
```

Impact : un utilisateur authentifié disposant d'un accès **Duo Agent Platform** peut, sous certaines conditions, sortir du sandbox de template d'un flow et provoquer une **exécution arbitraire de commandes sur le Self-Hosted AI Gateway**.

Prérequis :
- vecteur réseau ;
- authentification requise ;
- faibles privilèges ;
- accès Duo Agent Platform ;
- aucune interaction utilisateur ;
- concerne le composant **GitLab AI Gateway auto-hébergé**, pas toutes les installations GitLab.

Versions AI Gateway affectées :
- >= 18.1.6 et < 19.2.4 ;
- >= 19.3 et < 19.3.2 ;
- >= 19.4 et < 19.4.1.

Versions AI Gateway corrigées :
- 19.2.4 ;
- 19.3.2 ;
- 19.4.1.

**Action urgente uniquement si Self-Hosted AI Gateway utilisé :** mettre à jour immédiatement l'AI Gateway vers une version corrigée. Les utilisateurs de GitLab-hosted AI Gateway sont indiqués comme protégés par GitLab.

- **Sans authentification :** CVE-2026-4523 reste notable sur les versions GitLab affectées.
- **Auth bypass critique :** aucune nouvelle vulnérabilité de ce type identifiée aujourd'hui.

# Proxmox VE

## État actuel

```text
pve-manager              9.2.21
kernel no-subscription   7.0.14-20-pve
kernel précédent         7.0.14-19-pve
```

`pve-manager 9.2.21` reste la dernière version du dépôt no-subscription.

Le kernel `7.0.14-20-pve` est maintenant présent dans pve-no-subscription. Cependant, des retours récents du forum Proxmox signalent :
- perte de l'accès à l'horloge matérielle / `/dev/rtc0` sur certains systèmes ;
- problèmes PCIe AER/DPC avec certains contrôleurs Realtek RTL8168/RTL8111 utilisant r8169.

Un `7.0.14-21-pve` est testé pour certains problèmes, mais au moins un retour indique que la régression Realtek persiste dans ce build de test.

Ces éléments sont des **signaux de régression**, pas des avis de sécurité officiels.

**Action MCO :**
- tester `7.0.14-20-pve` sur un nœud pilote avant déploiement généralisé ;
- conserver `7.0.14-19-pve` installé et bootable pour rollback ;
- vérifier RTC, réseau, PCIe/AER et stockage après reboot ;
- ne pas promouvoir `7.0.14-21-pve` depuis pve-test sans besoin précis et validation.
