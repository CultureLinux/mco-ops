# MCO Daily — 6 octobre 2026

## Résumé exécutif

- **Rocky/RHEL 9** : cible inchangée, `5.14.0-687.54.1.el9_8` via RHSA-2026:74438. Aucun kernel plus récent identifié ce matin.
- **GitLab Self-Managed** : aucune nouvelle Critical Patch CE/EE depuis le 23 septembre. Cibles : `19.4.1`, `19.3.3`, `19.2.7`. Le correctif AI Gateway pour CVE-2026-90970 reste requis uniquement pour les Self-Hosted AI Gateway affectés.
- **Proxmox VE** : vigilance renforcée sur `7.0.14-20-pve`. Plusieurs retours récents isolent des régressions matérielles, notamment Broadcom `bnxt_en`. Un build de test `7.0.14-22~bnxt-test1` donne des résultats positifs chez plusieurs testeurs, mais ne doit pas être promu en production avant publication officielle.

## Rocky Linux / RHEL 9

Kernel courant : `5.14.0-687.54.1.el9_8`, RHSA-2026:74438, publié le 2 octobre 2026.

Correctifs sécurité suivis :
- CVE-2026-45856 — RDMA/uverbs ;
- CVE-2026-63794 — KVM/SVM AMD SEV, CVSS 7.0 ;
- CVE-2026-80775 — futex.

Action : poursuivre le déploiement de `687.54.1`, rebooter en fenêtre contrôlée et vérifier le kernel actif.

## GitLab Self-Managed

Versions corrigées CE/EE : `19.4.1`, `19.3.3`, `19.2.7`.

Le Critical Patch du 23 septembre corrige notamment deux vulnérabilités critiques CVSS 9.9, CVE-2026-89078 et CVE-2026-93577, touchant le traitement de configurations CI/CD. Sont également suivies CVE-2026-84739, CVE-2026-92470, CVE-2026-92874 et CVE-2026-4523. Cette dernière concerne un accès non authentifié à certaines traces CI/CD sur les versions affectées.

Self-Hosted AI Gateway : CVE-2026-90970, CVSS 9.9. Versions corrigées du composant : `19.2.4`, `19.3.2`, `19.4.1`. Les GitLab-hosted AI Gateways sont déjà corrigés selon GitLab.

Action : terminer les mises à niveau CE/EE et, si un Self-Hosted AI Gateway est utilisé, mettre également ce composant à niveau.

## Proxmox VE

État suivi :
- `pve-manager 9.2.21`
- kernel no-subscription `7.0.14-20-pve`
- fallback recommandé `7.0.14-19-pve`

Plusieurs retours récents signalent avec `7.0.14-20-pve` des pertes réseau sur certaines cartes Broadcom BCM574xx/`bnxt_en` ainsi qu'un crash reproductible dans un scénario de passthrough USB. Le retour à `7.0.14-19-pve` rétablit le fonctionnement dans ces cas.

Nouveauté : Proxmox teste `7.0.14-22~bnxt-test1`; plusieurs testeurs indiquent que la régression Broadcom disparaît. Ce build reste expérimental.

Action :
- ne pas généraliser `-20` sans validation sur un nœud pilote ;
- conserver `-19` bootable ;
- contrôler réseau, journal kernel, PCIe/AER, stockage et RTC après reboot ;
- attendre un kernel corrigé officiellement promu plutôt que déployer le build de test.
